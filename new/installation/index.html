Installation#

The Getting started page installs CHASE in two commands. This page has the rest, by what you want to do:

  • the Python package, with its optional parts;
  • the tools that run the checks;
  • the sources: all the modules at once, or one by one;
  • AI agents, through the MCP server.

The Python package#

$> pip install chase-cps

The package has the CHASE library (the C++ core library and its Python interface), the parsers of the specification files and of the DSL, the chase-cps command, and the diagrams. Wheels are available for Python 3.10 to 3.15 on Linux (x86_64 and aarch64, glibc 2.28 or later) and macOS 11 or later (arm64 and x86_64). Windows is not supported: use WSL.

Two parts are optional, installed with the package:

$> pip install "chase-cps[z3,rtl]"
  • z3 (the solver z3) checks the formulas over a bounded number of steps (static contracts, signal temporal logic) and the real variables, and is needed for repair and optimization (SMT and optimization).
  • rtl (Yosys, compiled to WebAssembly) reads Verilog and SystemVerilog, for the hardware checks.

The tools that run the checks#

The checks call external tools, installed apart from the package:

  • nuXmv for the checks of contracts and LTL (refinement, consistency, compatibility, implementation, cores). NuSMV can replace it.
  • slugs for GR(1) realizability and synthesis.
  • ESBMC or CBMC for the C programs.

chase-cps install installs them into ~/.chase, and chase-cps doctor lists the tools found, what each is needed for, and how to install the others:

$> chase-cps install nuxmv --accept-license    # Linux x86_64, macOS arm64
$> chase-cps install nusmv                     # Linux x86_64
$> chase-cps install slugs                     # needs a C++ compiler, make, and Boost
$> chase-cps install esbmc                     # Linux; on macOS: brew install esbmc
$> chase-cps doctor

CBMC comes from its packages (brew install cbmc, apt install cbmc). gr1c is needed only for the specifications that CHASE writes for it, and is installed from its sources.

The tools are looked up in the PATH and in ~/.chase/bin, or given with the environment variables CHASE_NUXMV, CHASE_NUSMV, CHASE_SLUGS, CHASE_ESBMC, and CHASE_CBMC.

On macOS, nuXmv needs the libraries of Homebrew (brew install libxml2 gmp libedit). On Linux it needs libxml2 and libedit2, and the C++ library of GCC 13 or later (Ubuntu 24.04, Debian 13, Fedora 39, or newer).

Without nuXmv

nuXmv is free for academic and non-commercial use only. Otherwise the checks run with NuSMV (LGPL) instead. NuSMV has no real type: the real variables are then checked with exact regions when they are only compared with constants, and with predicate abstraction otherwise.

From the sources#

The sources are needed for the console tools logics_tool and dsl_tool, for the C++ library, and to work on CHASE. They need CMake 3.18 or later, a C++17 compiler, Python 3 with its development files, and pybind11:

$> sudo apt-get install build-essential cmake git python3-dev pybind11-dev uuid-dev
$> brew install cmake pybind11

All the modules at once#

The chase repository has every module as a submodule, and a script that builds and installs them in order:

$> git clone --recursive https://github.com/chase-cps/chase
$> cd chase
$> ./install.sh /path/to/install/directory

At the end, the script prints the lines to add to the shell configuration:

export PATH="/path/to/install/directory/chase/bin:$PATH"
export PYTHONPATH="/path/to/install/directory/chase/lib:$PYTHONPATH"

The Python modules are built for the interpreter given by the PYTHON environment variable (by default python3). In the same repository, pip install . builds and installs the Python package.

One module at a time#

Each module is a repository of the chase-cps organization, and only the ones a task needs have to be cloned:

  • core-library: the C++ library that represents contracts and computes their algebra, with its Python interface. Every other module needs it.
  • chase-backends: writes the inputs of nuXmv, slugs, and gr1c from the contracts.
  • third_party: the runtime of ANTLR4 (version 4.5.4), used by the two parsers below.
  • logics_tool: reads the specification files and runs the console.
  • DSL_tool: reads the design-pattern language (DSL) of the power systems.

For the C++ library alone, core-library is enough; to write the inputs of the tools, add chase-backends; for logics_tool or dsl_tool, add third_party and the tool. All the modules are installed in one directory, given by the variable CHASE_INSTALL_DIR:

$> export CHASE_INSTALL_DIR=/absolute/path/to/install/directory

core-library comes first; then chase-backends and third_party; then logics_tool and DSL_tool. Each module is built the same way:

$> git clone https://github.com/chase-cps/<module> <module>
$> cmake -S <module> -B <module>/build -Dpybind11_DIR=<path to pybind11Config.cmake>
$> cmake --build <module>/build
$> cmake --install <module>/build

The modules are built in Release mode; -DCMAKE_BUILD_TYPE=Debug builds them for debugging, and -DPython_EXECUTABLE=<python> chooses the Python interpreter. On macOS with Homebrew, -DCMAKE_PREFIX_PATH=$(brew --prefix) finds pybind11 in place of -Dpybind11_DIR. cmake --build core-library/build --target doc writes the documentation of the C++ library with Doxygen.

The libraries are installed in CHASE_INSTALL_DIR/chase/lib, the headers in CHASE_INSTALL_DIR/chase/include, the console tools in CHASE_INSTALL_DIR/chase/bin, and ANTLR4 in CHASE_INSTALL_DIR/third_party.

AI agents#

The MCP server gives the operations of CHASE to an AI agent (Claude Code, Codex, Cursor, and other clients). With uv, nothing is installed by hand:

$> claude mcp add chase -- uvx chase-mcp

or pip install chase-mcp and the command chase-mcp. The agent skill, which tells the agent how to use the tools, and the settings of the other clients are on the MCP server page. The server needs the same tools as the checks (chase-cps doctor).

An extension for VS Code, which draws the diagrams in the editor, is in preparation.
