Interfaces#

The operations of CHASE have the same names in every interface. Here is one contract, an arbiter that grants every request when the requests stop infinitely often, and the check that an implementation that grants at the next step refines it, in each interface: Python, the CHASE specification language (Spec), the command line (CLI), SystemVerilog Assertions (SVA), and the MCP server for AI agents (MCP).

from chase_cps import Contract, refines

spec = Contract.from_strings(inputs=["req"], outputs=["grant"],
                             assumptions=["G F !req"],
                             guarantees=["G (req -> F grant)"], name="Spec")
impl = Contract.from_strings(inputs=["req"], outputs=["grant"],
                             guarantees=["G (req -> X grant)"], name="Impl")
print(refines(impl, spec).status)    # valid
NAME: arbiter;

CONTRACT Spec:
    input boolean variable req;
    output boolean variable grant;
    Assumptions:
        G(F(!req));
    Guarantees:
        G(req -> F(grant));

CONTRACT Impl:
    input boolean variable req;
    output boolean variable grant;
    Assumptions:
        true;
    Guarantees:
        G(req -> X(grant));
$> chase-cps check arbiter.ltl --refines Impl Spec
refines     Impl <= Spec                             valid           0.03 s
module spec (input logic clk, input logic req, output logic grant);
  A1: assume property (@(posedge clk) s_eventually !req);
  G1: assert property (@(posedge clk) req |-> s_eventually grant);
endmodule

parse_sva reads this module as the contract Spec: the ports give the inputs and the outputs, assume the assumptions, and assert the guarantees.

The interfaces are:

  • Python package: for scripts and notebooks (pip install chase-cps).
  • Command line: to check or draw a specification file (chase-cps check, chase-cps view).
  • Specification language and console: the .ltl files of CHASE, and the console of logics_tool.
  • SystemVerilog Assertions: contracts read from SVA, and written back as SVA.
  • MCP server for AI agents: the operations as tools of an agent, with a skill that tells the agent how to use them.
  • Diagrams: contracts, components, and systems drawn as a web page, with the results of the checks.

Model checking, GR(1) synthesis, and the tools that read SystemVerilog are described in Tool integrations.
