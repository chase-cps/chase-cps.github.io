Fire-suppression drones in C: a collision found and fixed on the contracts, then checked one function at a time#

The system. Two drones of a fire-suppression mission move on a 10 x 10 grid, one cell per step. They come from the multi-drone fire suppression of ContrACT (Xiao et al., MEMOCODE 2026), whose software is written as reactions, pieces of code run at each step. Each step has five parts, each with a contract and a C function:

  • Plan0 and Plan1 (plan.c): each drone at (x, y) asks for a move r toward its target (tx, ty): 0 stay, 1 right, 2 left, 3 down, 4 up;
  • Coordinator (coordinator.c, function grant): grants the moves g, refusing two moves into the same cell or a swap;
  • Move0 and Move1 (move.c): each drone moves as granted, to (nx, ny).

The requirement Fleet: two drones in different cells are, after the step, in different cells, and do not cross. The contracts are on integers, checked by z3; the C functions by ESBMC.

The question. Can two drones end in the same cell? And can each C function be checked alone, without checking the whole program? A whole program check grows with every function; one function at a time does not.

The system: one step of the two drones inside the requirement Fleet; each part has its C function.

The steps#

Step 1. The contracts do not refine the requirement. The five parts composed do not refine Fleet (some behavior of the parts breaks it). In the counterexample, drone 0 is at its target (1, 0) and stays, and drone 1 at (2, 0) moves left into its cell: the coordinator compares only drones that both move. The script finds the same failure for a swap.

Step 1: the parts with Coordinator do not refine Fleet.

Step 2. The fix. No number can be tuned: the rule must change. CHASE computes the quotient of Fleet by the other four parts: the weakest contract the coordinator must meet so that the step meets Fleet (see the contract algebra). Coordinator does not refine it. CoordinatorSafe, which grants a move only into a cell that is free after the step, does, and the parts with it refine Fleet.

Step 2: the parts with CoordinatorSafe refine Fleet.

Step 3. The code. ESBMC checks each function against its contract (the tag M ⊨ C), in about 0.1 s each. The five functions of the step (plan0, plan1, grant, move0, move1) implement theirs. grant does not implement CoordinatorSafe; grant_safe does. With steps 2 and 3, the C code with grant_safe keeps the drones apart, and the whole program is never checked at once.

Step 3: grant_safe implements CoordinatorSafe.

The tags of the pictures are explained on the page Diagrams.

Run it#

pip install "chase-cps[z3]"      # and ESBMC or CBMC
python dronegrid.py --expect

The files of the demo are in the repository; Running the demos says what the scripts print and how to use the diagrams.
