Payment assistant agent: the plan of an AI agent checked before it runs#

The system. An AI agent gets a task from a user and splits it among sub-agents, each holding some of the tools. The task comes from AppWorld, a benchmark of agents that use phone apps: pay Kristin back on Venmo the amount in her text messages, with the note "Groceries", then text her "It is done.", and send no voice message. Each variable is a tool call or what it writes: tx2 (a payment made by sub-agent 2), paid (the payment is done), text3 (a text sent by sub-agent 3), desc_ok and msg_ok (the note and the text are the ones asked for), voice1, voice3 (voice messages), complete (the task marked done). The contract of the parent, Parent, is the request and the rules of the user, written in LTL; it assumes nothing. The sub-agents are Messages (finds the amount), Payment (pays), Text (sends the text), and Keep, what the parent keeps for itself (marking the task complete). Each sub-agent gets a contract from the tools it holds. nuXmv checks the contracts.

The question. Do the contracts of the sub-agents, together, give the contract of the parent? If not, what must a sub-agent promise? The answer is known before any tool is called, so a plan with a gap is fixed before it pays anyone.

The plan: the four sub-agents inside the contract of the parent.

The steps#

The tags on the boxes give the results of the checks: green holds, red fails; Diagrams says how to read them.

Step 1. The plan does not refine the parent. The plan refines the parent (⪯) when every behavior of the sub-agents together meets the contract of the parent. It does not: no sub-agent promises F text3 (the text is sent, sooner or later). nuXmv gives a run that pays and never sends the text.

Step 1: the plan does not refine the parent; in the counterexample text3 stays false.

Step 2. What sub-agent 3 must do. CHASE computes the quotient Q3 = Parent / (Messages ⊗ Payment ⊗ Keep): the weakest contract that the missing sub-agent must meet so that the plan refines the parent. It is derived from the contracts, not written by hand. Q3 asks for the rules of the tools of sub-agent 3 and F text3. Text, with F text3 added, refines Q3 (it is drawn in Q3, the dashed box), so the plan refines the parent.

Step 2: Text, with F text3 and the assumption F paid, refines Q3.

Step 3. A rule against the request. If the parent also says "never pay" (G !tx2, in ParentWithSlip), no behavior meets its contract: it is inconsistent. CHASE finds the unsat core, the smallest set of guarantees in conflict: F tx2 and G !tx2, two of nine.

Step 3: the inconsistent parent, with the core in red.

Run it#

pip install chase-cps
chase-cps install nuxmv --accept-license
python assistant.py --expect
